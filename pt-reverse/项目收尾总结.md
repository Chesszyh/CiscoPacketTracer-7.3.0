# Packet Tracer 7.3.0 CLI/MCP 化收尾总结

本文档记录本阶段围绕 Cisco Packet Tracer 7.3.0 自动化工具链完成的主要修改、当前可用能力、验证状态、后续优化方向和遗留边界。目标是让后续 agent 或人工继续工作时，不需要从会话记录里重新还原上下文。

更新时间：2026-06-11。

当前代码基线：

- 工具仓库 `CiscoPacketTracer-7.3.0`: `89908e5 Add removable plan config metadata`
- 父仓库 `Information-Security`: `7bffd19 Update CiscoPacketTracer automation submodule`

## 当前定位

本工具链不是替代 Packet Tracer GUI 的完整重实现，而是在固定版本 7.3.0 上提供 agent 友好的离线优先工作流：

- 用 CLI/MCP 生成拓扑 JSON、IP/VLAN 规划、IOS 配置、渲染图和实验交付包。
- 尽量使用本地已验证模型，避免 7.3.0 Script Module 容易崩溃的 API 和设备模型。
- 所有 live 操作默认受 `allow_live=true` 和 `dry_run=true` 保护，先预览命令，再由用户决定是否接触 Packet Tracer GUI。

## 已完成的主要修改

### 离线 CLI 工具

- 建立 `pt-reverse/bin/pt730-*` 命令族，覆盖能力查询、catalog、安全检查、IP 规划、拓扑组合、配置规划、IOS 模板、布局、渲染、lab 打包、pipeline、自检、模型验证和 live 桥接辅助。
- `pt730-selftest` 已成为回归入口，覆盖 Python 编译、JSON 示例、模板、安全策略、渲染、MCP 冒烟和 dry-run live 工具。
- `pt730-capabilities --compact` 能以机器可读 JSON 暴露当前 CLI/MCP 能力，便于 agent 决策。

### MCP 包装

- 增加 `pt730-mcp` stdio JSON-RPC wrapper。
- MCP 已覆盖离线工具、模板生成、schema 查询、渲染、lab bundle、配置导出、catalog、安全策略、模型验证和受控 live 工具。
- live 类 MCP 工具默认需要 `allow_live=true`；多数 live 工具支持 `dry_run=true`，只返回底层 CLI 命令，不接触 Packet Tracer。
- `pt730-app open` 默认先做 `.pkt` 离线预检；已知崩溃指纹和可见风险型号会阻止打开，只有人工抢救时才传 `--allow-risky`。

### 内置拓扑模板

当前 `pt730-template schema` 暴露以下模板：

- `lan-star`: 路由器、交换机、PC/Server 星型 LAN。
- `dual-stack-lan`: IPv4/IPv6 双栈 LAN，输出 IPv4 `pc_configs`、IPv6 `ipv6_configs`、IOS `ipv6 unicast-routing` 和 IPv6 验证清单。
- `wireless-lan`: 使用已验证 `AccessPoint-PT`、`Laptop-PT` 的无线 LAN。
- `vlan-router-on-stick`: 802.1Q 单臂路由、VLAN、静态或 DHCP 主机、可选 Server-PT 服务。
- `switching-lab`: STP、EtherChannel、trunk/access VLAN、PortFast/BPDU Guard 的二层交换实验。
- `server-services`: Server-PT HTTP/DNS/FTP/TFTP/Email/NTP/Syslog/DHCP 服务实验。
- `edge-security`: NAT overload、ACL、DMZ、内外网测试主机。
- `router-ring`: 2911 + HWIC-2T 串口路由器环。
- `wan-ring`: 多站点串口 WAN，支持 RIP/EIGRP/OSPF/static/none。
- `campus`: 代表性校园网，支持 L3、RIP/EIGRP/OSPF/static。
- `redundant-campus`: 双核心、双归属接入、HSRP、STP、DHCP relay/pools、NTP/Syslog/SNMP，支持 RIP/EIGRP/OSPF。
- `college-network`: 面向学院网课程设计，默认规划 1900 台 PC、50 台服务器、6 台三层交换机，输出完整 IP/VLAN 分配、代表拓扑、网站功能版块和 RIP/EIGRP/OSPF/static IOS 配置。
- `enterprise-edge`: HQ VLAN、server zone、DMZ、ISP/Internet、branch WAN、NAT/ACL 的综合企业边界拓扑，支持 RIP/EIGRP/OSPF/static/BGP 边界对等。

### IP/VLAN 与配置规划

- `pt730-ip-plan campus` 支持校园网 VLSM、网关预留和可供 compose 使用的 segment 输出。
- `pt730-compose campus` 能从高层 spec 生成设备、链路、代表性主机、服务器服务和布局。
- `pt730-config-plan campus` 支持 VLAN、access/trunk、L3 SVI、routed interlink、RIP、EIGRP、OSPF、static routes，并可导出每台设备 `.cfg`。
- `pt730-ios-template` 支持 VLAN、access/trunk/routed interfaces、接口 IPv6、IPv6 unicast routing、IOS 管理访问/本地用户/SSH/console/VTY/banner、STP、EtherChannel、DHCP relay、HSRP、IOS DHCP server、NTP/Syslog/SNMP、RIP/EIGRP/OSPF/BGP/static、OSPFv3/RIPng/IPv6 static、ACL、NAT 等高层配置片段。

### 渲染、审计与交付包

- `pt730-layout` 提供 deterministic layout，支持 `auto`、`hierarchical`、`campus`、`lan`、`ring`、`grid`。
- `pt730-plan` 提供通用 topology JSON 编辑入口，支持 `new`、metadata、设备/模块/链路的添加和删除、级联删除，以及无线 AP 元数据、注释、IPv4/IPv6 主机配置、VLAN、DHCP 池、Server-PT 服务、IOS 命令和安全策略的添加与删除；MCP 同步暴露 `pt730_plan_*` 工具，便于 agent 不手写 JSON 也能拼和修正自定义拓扑与配置元数据。
- `pt730-render` 支持 Mermaid、SVG、draw.io、HTML、Markdown、summary、course-audit、diagram-audit、verification-plan。
- Mermaid/SVG/draw.io/HTML 渲染支持主题、标题、图例、链路标签开关、模型标签开关、按网络/VLAN/site/category 分组和 `annotations` 说明框；CLI `--annotation`/`--annotations` 与 MCP `annotations` 还能临时追加说明框且不改源 JSON，`pt730-render schema` / `pt730_schema target=render` 可查询字段规范，Markdown/summary 会同步输出注释表、计数、课程设计 IP/VLAN 规划和网站功能版块。
- `preset=report` 面向报告截图，默认 paper theme、自动分组、图例、隐藏链路标签，并生成 diagram-audit 与 verification plan。
- `pt730-lab template` / `pt730-lab plan` 能一次性生成 topology、safety、render bundle、configs、manifest。
- lab bundle 支持 `render.annotations`、CLI `--annotation`/`--annotations` 和 MCP `annotations`，可把报告说明框写入完整交付包。
- `pt730-lab report` 能从 manifest 生成课程/实验交付索引。

### 安全和模型验证

- `pt730-safety plan` 检查未知设备、未知端口、risky/blocked 模型、未验证模块、未验证线缆、IPv4/IPv6 地址、DHCP pool、IOS 接口配置和串口 clock-rate 风险。
- `pt730-safety js` 拦截高风险 JavaScript 片段，例如已知危险的 DHCP client run API。
- 维护了本地模型安全 overlay。当前安全模型包括 `2911`、`2960-24TT`、`PC-PT`、`Server-PT`、`1841`、`1941`、`2901`、`2950-24`、`Laptop-PT`、`AccessPoint-PT`、`Cloud-PT`。
- 已验证模块包括 `HWIC-2T`；已验证线缆包括 Ethernet straight/crossover 和 2911 serial。
- `3560-24PS`、`3650-24PS`、ASA、IP Phone、Printer、WRT300N 等仍按 risky/blocked 思路处理，避免无人值守创建导致崩溃。
- 用户提供的 `crash.pkt` 是已知坏样本，其 SHA-256 指纹已加入 `.pkt` open 预检；该文件本身不应提交到仓库。

## 仍需注意的边界

- “所有 Packet Tracer 功能完全 CLI 化”尚未完成。当前成果更接近稳定的 agent-first 子集，而不是完整 GUI 覆盖。
- 7.3.0 live Script Module 仍然容易崩溃；不要并发 live 操作，不要无人值守批量测试 risky 模型。
- IPv6 路由器/三层交换机 IOS 片段已可离线生成和摘要解析；IPv6 主机 GUI 写入尚未 live API 验证，`dual-stack-lan` 目前仍把 IPv6 PC/Server 配置作为报告/手工配置元数据输出。
- DHCP client live 租约验证仍是 guarded 路径；离线生成可用，live 验证需 dry-run 后小步执行。
- 无线链路 code `8109` 仍会在非 strict safety 下提示未完全 live 验证。
- ASA、防火墙、IP Phone、Printer、WRT、物理电源类对象仍不适合默认自动创建。
- `.pkt` 文件、截图、dump、Cisco 程序文件、`src/` 和运行输出默认不纳入 Git。

## 后续优化方向

下面按优先级列出后续值得继续推进的方向。优先级的判断标准是：是否能进一步降低 agent 手工干预、是否能减少 live 崩溃风险、是否能覆盖课程和常见实验的真实需求。

1. 扩展 live 反向导入与差异同步

   当前可以 query/export live canvas，并能离线 summarize query。下一步可以把 live query 更完整地转换为 topology plan，再提供 `diff` / `patch` 类命令，让 agent 能比较“当前 PT 画布”和“期望 JSON plan”的差异，只应用最小变更。

2. 增强 Packet Tracer GUI 服务面板写入验证

   Server-PT HTTP/DNS/FTP/TFTP/Email/NTP/Syslog/DHCP 已有离线元数据和 guarded live 工具。后续应对每个服务做小规模 live create/query/save/reopen 验证，记录字段兼容性，避免把未验证 GUI 字段误标为稳定自动化能力。

3. 补齐 IPv6 主机 GUI 配置路径

   IOS IPv6、OSPFv3、RIPng、IPv6 static 和 host IPv6 元数据已经能离线生成。后续重点是验证 PC-PT、Laptop-PT、Server-PT 的 IPv6 GUI 写入 API，并为 `pt730-live_pc_*` 或新工具增加 IPv6 static/inspect。

4. 建立模型验证批次和证据库

   目前 safe/risky/blocked overlay 已能记录模型状态。后续可以继续小批量验证常见 PT 7.3.0 设备，尤其是更多路由器、交换机、无线和终端模型，并把失败原因、dump 或截图路径写入 evidence，提升 catalog 的可信度。

5. 改进复杂拓扑视觉布局

   现有 layout 已能服务报告和课程拓扑。后续可加入更强的自动分层、链路避让、端口密度控制、站点/楼宇/机房分组和大型画布分页导出，使 50+ 设备拓扑更适合直接截图、讲解和提交。

6. 提供 agent 级高层任务入口

   目前有模板、pipeline、lab bundle 和 MCP 工具。后续可增加更高层的 `pt730-design` 或 `pt730-agent` 命令，用一份课程/实验需求 JSON 自动选择模板、规划 IP、生成配置、渲染报告、输出验证脚本和录屏讲解提纲。

7. 增强文档生成和课程报告对接

   当前 lab report 是交付索引。后续可让 report 直接生成课程报告章节草稿，包括拓扑设计理由、IP/VLAN 表、设备配置摘要、路由协议说明、验证结果记录表和视频讲解大纲。

8. 更细粒度的安全策略

   现有 safety 能识别模型、端口、线缆、DHCP、IOS 和 JS 风险。后续可以增加 policy profile，例如 `coursework`、`live-safe`、`exploratory`，让 agent 根据场景自动采用不同严格度。

## 建议的收尾使用方式

常规离线检查：

```bash
pt-reverse/bin/pt730-selftest
pt-reverse/bin/pt730-mcp --list-tools
pt-reverse/bin/pt730-capabilities --compact
```

生成一个报告友好的实验包：

```bash
pt-reverse/bin/pt730-template redundant-campus --segments 4 --hosts-per-segment 2 --servers 4 --routing ospf --output topology.json
pt-reverse/bin/pt730-lab plan topology.json --output-dir lab-out --basename topology --preset report
pt-reverse/bin/pt730-lab report lab-out/manifest.json --output lab-out/deliverable.md
```

MCP agent 推荐入口：

```bash
pt-reverse/bin/pt730-mcp
```

Codex skill 安装：

```bash
ln -sfn "$PWD/pt-reverse/skills/cisco-packet-tracer-730" "$HOME/.codex/skills/cisco-packet-tracer-730"
```
