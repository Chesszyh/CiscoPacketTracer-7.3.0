# Cisco Packet Tracer 7.3.0 自动化工具中文使用手册

本文档面向本仓库的实际使用者，说明如何用 `pt-reverse/bin/pt730-*`
工具对固定版本 Cisco Packet Tracer 7.3.0 做离线拓扑审计、受控 live
自动化、IP/VLAN 规划、内置拓扑模板、单规格 Lab Bundle、一键离线流水线、拓扑组合、配置规划、拓扑自动布局、IOS 配置模板渲染、模型安全验证和当前画布反向导出。

本工具链的定位不是替代 Packet Tracer 全部 GUI 功能，而是在 7.3.0 这个
固定版本上提供一套可复现、可审计、尽量不崩溃的命令行工作流。

## 基本原则

1. 固定使用 Cisco Packet Tracer 7.3.0。不要因为新版文档或新版 MCP 项目
   可用就切换版本。
2. 默认先跑离线命令。`pt730-selftest`、`pt730-template`、`pt730-lab`、`pt730-pipeline`、
   `pt730-ip-plan`、`pt730-compose`、`pt730-config-plan`、`pt730-layout`、
   `pt730-safety`、`pt730-render` 不接触 live Packet Tracer，适合日常修改后验证。
3. live 操作一次只做小步。尤其是新模型验证，必须单个设备、单次创建、
   单次 query、保存、重开后再记录为 safe。
4. 不自动使用 risky/blocked 模型。它们可能被 PT 拒绝、导致查询不完整，
   或触发 7.3.0 崩溃。
5. 保存 `.pkt`、截图、live query 结果可以作为本地证据，但默认不提交到 Git。

## 首次准备

先确保子模块完整：

```bash
git submodule update --init --recursive
```

确认本地 PT 程序存在。当前脚本会按顺序寻找：

```text
$PT_BIN/PacketTracer7.exe
./Cisco Packet Tracer 7.3.0/bin/PacketTracer7.exe
./src/bin/PacketTracer7.exe
```

如果你的安装目录不同，可以显式指定：

```bash
export PT_BIN="/path/to/Packet Tracer/bin"
```

常用依赖包括：

```text
python3
bash
tmux
curl
ss
wine
```

截图或桌面辅助操作可能用到 `grim`、`import`、`xdotool`、`wmctrl`，但核心
命令不依赖这些工具。

## Codex skill 包装

仓库内置了一个可发布的 Codex skill：

```text
pt-reverse/skills/cisco-packet-tracer-730
```

在本机让 Codex 自动发现它：

```bash
ln -sfn "$PWD/pt-reverse/skills/cisco-packet-tracer-730" \
  "$HOME/.codex/skills/cisco-packet-tracer-730"
```

之后可用 `$cisco-packet-tracer-730` 触发。这个 skill 默认走离线 CLI：
模板、IP 规划、拓扑组合、配置规划、布局、SVG/draw.io/HTML/Markdown 渲染、
课程审计和安全检查；除非用户明确要求，不会启动 live Packet Tracer。

## MCP stdio 包装

`pt730-mcp` 把主要离线 `pt730-*` 命令暴露成 MCP tools，供支持 MCP 的
agent 通过 stdio 调用：

```bash
pt-reverse/bin/pt730-mcp --list-tools
pt-reverse/bin/pt730-mcp
```

最小 JSON-RPC smoke 示例：

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pt730_render","arguments":{"format":"summary","plan":"pt-reverse/examples/simple-lan.json"}}}' \
  | pt-reverse/bin/pt730-mcp
```

当前 MCP 暴露离线安全工具和受控 live 工具。capabilities、template、IP plan、
compose、config plan、plan editor、layout、render、safety、IOS template、config export 和
campus pipeline 可以直接用于离线工作流。live Packet Tracer 创建/查询/保存
必须显式传 `allow_live=true`；`pt730_live_apply` 在 `dry_run=true` 时仍然是
离线预检，不会接触 PT。

MCP 也暴露了离线 query/model 辅助工具：

- `pt730_schema`: 离线读取 `template`、`ip_plan`、`compose`、`config_plan`、`pipeline`、`lab`、`render`、`plan`、`ios_template` 的输入 schema 和示例，适合 agent 在生成规格 JSON 前调用。
- `pt730_plan_new` / `pt730_plan_add_device` / `pt730_plan_add_module` / `pt730_plan_add_link` / `pt730_plan_add_ap_config` / `pt730_plan_add_annotation` / `pt730_plan_add_pc_config` / `pt730_plan_add_ipv6_config` / `pt730_plan_add_vlan_config` / `pt730_plan_add_dhcp_pool` / `pt730_plan_add_server_config` / `pt730_plan_add_ios_config` / `pt730_plan_add_security_policy`: 离线创建并逐步编辑 topology JSON，适合 agent 不手写 JSON 也能拼出自定义拓扑、串口模块、无线 AP 元数据、主机地址、VLAN、DHCP、Server-PT 服务、IOS 命令和安全策略元数据。
- `pt730_render`: 离线渲染 Mermaid、SVG、draw.io、HTML、Markdown、summary、课程审计、拓扑图质量审计和验证清单；MCP 参数已覆盖 `preset`、`theme`、`title`、`legend`、`link_labels`、`model_labels`、`group_by` 等可视化控制项。
- `pt730_render_bundle`: 对同一个拓扑 plan 一次性生成 SVG、draw.io、HTML、Markdown、summary、可选课程审计、可选拓扑图质量审计、可选验证清单和 manifest，适合 agent 直接产出一组报告/审阅附件；`preset=report` 会默认使用报告友好的 paper 主题、自动分组、图例、隐藏链路标签，并生成 `diagram-audit`、`verification-json`、`verification-md`。
- `pt730_verification_plan`: 从 topology JSON 离线生成 JSON 或 Markdown 验证清单，不启动 Packet Tracer；每条检查都包含手工操作、对应 CLI 命令和默认 `dry_run=true` 的 MCP live 工具参数。
- `pt730_lab_template`: 从一个模板规格 JSON 一次性生成 `topology.json`、`safety.json`、`render/`、`configs/` 和 `manifest.json`，适合 agent 把课程实验或演示拓扑做成完整离线交付包。
- `pt730_lab_plan`: 从一个已有 topology plan JSON 生成同样的完整离线交付包，适合 agent 先用 compose/layout/自定义 JSON 生成复杂拓扑，再统一打包审阅产物。
- `pt730_lab_report`: 从 lab bundle 的 `manifest.json` 生成 Markdown 交付索引，汇总拓扑、渲染图、安全检查、配置文件和录屏讲解建议。
- `pt730_template_lan_star` / `pt730_template_dual_stack_lan` / `pt730_template_wireless_lan` / `pt730_template_vlan_router_on_stick` / `pt730_template_switching_lab` / `pt730_template_server_services` / `pt730_template_edge_security` / `pt730_template_router_ring` / `pt730_template_wan_ring` / `pt730_template_campus` / `pt730_template_redundant_campus` / `pt730_template_enterprise_edge`: 离线生成内置模板拓扑，MCP 参数已覆盖 CLI 的 `dns`、IPv6 prefix/gateway、`ssid`、802.1Q、trunk/access VLAN、STP、EtherChannel、Server-PT HTTP/DNS/FTP/TFTP/Email/NTP/Syslog/DHCP、router DHCP pools、DHCP client hosts、NAT/ACL、DMZ、HSRP/STP、DHCP relay、分支 WAN、ISP/Internet、WAN/校园网 RIP/EIGRP/OSPF/static 路由、企业边界 BGP、`layout_style`、`no_layout`、`compact`、`l3`、`routing` 等选项。
- `pt730_ip_plan_campus` / `pt730_compose_campus` / `pt730_pipeline_campus`: 离线执行校园网规划、组合和流水线生成，MCP 参数已覆盖 `compact` 和 `layout_style` 等工作流控制项。
- `pt730_layout`: 离线自动布局拓扑，MCP 参数已覆盖 `canvas_width`、`canvas_height`、`spacing_x`、`spacing_y`、`margin`、`compact` 等画布控制项。
- `pt730_config_plan_campus` / `pt730_export_configs`: 离线生成和导出 IOS 配置，MCP 参数已覆盖 `ios_only`、`source`、`compact` 等配置导出控制项。
- `pt730_catalog`: 离线查询设备、端口、模块、线缆和别名 catalog，并带本地 PT 7.3.0 安全状态 overlay。
- `pt730_safety_js`: 离线检查准备传给 `pt730-eval` 的 JavaScript 是否命中高风险调用。
- `pt730_safety_policy`: 输出当前模型、模块、线缆和 JS 风险策略。
- `pt730_topo_summarize_query`: 离线汇总保存下来的 `pt730-topo query` JSON。
- `pt730_topo_export`: 带 `from_query` 时离线导出 raw/summary/Markdown；不带 `from_query` 时属于 live query 导出，必须 `allow_live=true` 或 `dry_run=true`。
- `pt730_models_manifest`: 读取模型安全 registry。
- `pt730_models_queue`: 读取待验证模型队列。
- `pt730_models_probe_plan`: 为单个模型生成验证拓扑。
- `pt730_models_validate`: 运行模型验证 dry-run，或在 `allow_live=true` 下执行 live 验证。
- `pt730_models_validate_batch`: 批量模型验证 dry-run，或在 `allow_live=true` 下执行 live 验证。
- `pt730_models_record`: 记录模型验证结果；真实写入必须 `allow_write=true`，否则只能 `dry_run=true` 预览命令。

设备级 live MCP 工具也支持 `dry_run=true` 命令预览，不会连接 Packet Tracer：

- `pt730_live_ios`: 预览或执行路由器/交换机 IOS 命令。
- `pt730_live_pc_inspect`: 预览或执行 PC/Server/Laptop 端口 IP 状态读取。
- `pt730_live_pc_static`: 预览或执行 PC/Server 静态 IPv4 配置。
- `pt730_live_pc_dhcp`: 预览或执行 PC/Server/Laptop DHCP 开启、renew 和租约等待。
- `pt730_live_term`: 预览或执行通用终端命令，可等待并匹配输出。
- `pt730_live_ping`: 预览或执行 IOS ping 检查。
- `pt730_live_server_inspect`: 预览或执行 Server-PT 服务状态检查。
- `pt730_live_server_service`: 预览或执行 Server-PT HTTP/DNS/FTP/TFTP/NTP/Syslog/SMTP/POP3/Email/DHCP 开关。
- `pt730_live_server_dns_add`: 预览或执行 Server-PT DNS A 记录添加。
- `pt730_live_server_ftp_add`: 预览或执行 Server-PT FTP 用户添加。
- `pt730_live_server_ftp_remove`: 预览或执行 Server-PT FTP 用户删除。
- `pt730_live_server_email_add`: 预览或执行 Server-PT Email 用户添加，并可设置 SMTP 域名。
- `pt730_live_server_email_remove`: 预览或执行 Server-PT Email 用户删除。
- `pt730_live_server_ntp_config`: 预览或执行 Server-PT NTP 启停、认证、key-id 和 MD5 配置。
- `pt730_live_server_syslog_config`: 预览或执行 Server-PT Syslog 启停和 UDP 端口配置。
- `pt730_live_server_dhcp_config`: 预览或执行 Server-PT DHCP 池配置。
- `pt730_live_ftp`: 预览或执行 PC 侧 FTP 客户端登录和命令序列。
- `pt730_live_sim`: 预览或执行 simulation/PDU 的 status、reset、fast-forward、event-list、simple-pdu。
- `pt730_live_app`: 预览或执行 appWindow 的 count/save/new/open/save-as/screenshot。
- `pt730_live_bridge`: 预览或执行 bridge 的 start/stop/restart/status/bootstrap/logs。
- `pt730_live_launch`: 预览或执行 Packet Tracer tmux launcher 的 start/stop/restart/status/logs。
- `pt730_live_recover`: 预览或执行 bridge + Packet Tracer 恢复流程。
- `pt730_live_eval`: 预览或执行受防护的 Packet Tracer JavaScript eval。
- `pt730_live_smoke`: 预览或执行完整 bridge/server/DNS/FTP/save smoke 流程。

例如预览 IOS 命令：

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pt730_live_ios","arguments":{"device":"R1","commands":["show ip interface brief"],"dry_run":true}}}' \
  | pt-reverse/bin/pt730-mcp
```

如果去掉 `dry_run=true`，这些设备级 live 工具都必须显式传
`allow_live=true`，否则 MCP 会返回协议错误，防止 agent 默认误触崩溃风险路径。

## 模型安全状态

模型状态由内置 registry 和 `pt-reverse/pt730/model_validations.json` overlay
共同决定。

查看当前状态：

```bash
pt-reverse/bin/pt730-models manifest
```

当前已验证汇总：

```text
safe: 2911, 2960-24TT, PC-PT, Server-PT, 1841, 1941, 2901,
      2950-24, Laptop-PT, AccessPoint-PT, Cloud-PT

risky: 4321, 4331, 2950T, 3560-24PS, 3650-24PS, Printer-PT,
       WRT300N, ASA5505, ASA5506, IP Phone

blocked: Power Distribution Device

unverified: 当前常用队列为空
```

含义：

- `safe`: 本地 PT 7.3.0 live 创建、query、保存、重开、再 query 通过。
- `unverified`: catalog 里有，但当前环境尚未验证。
- `risky`: PT 拒绝创建、query 不稳定，或已有崩溃风险证据。
- `blocked`: 不应自动化创建或使用。

安全策略会阻止默认使用 risky/blocked 模型。例如：

```bash
pt-reverse/bin/pt730-safety plan topology.json
pt-reverse/bin/pt730-topo apply --dry-run topology.json
```

如果确实要研究 risky 模型，只能使用显式验证命令，并做好崩溃准备。

## 离线拓扑渲染和课程审计

离线渲染不会启动 Packet Tracer，适合写报告、检查 IP 规划、生成拓扑说明和
可打开预览的 SVG 拓扑图。

生成 Mermaid：

```bash
pt-reverse/bin/pt730-render mermaid pt-reverse/examples/simple-lan.json
```

生成 Markdown：

```bash
pt-reverse/bin/pt730-render markdown pt-reverse/examples/simple-lan.json
```

从零创建一个自定义拓扑 JSON：

```bash
pt-reverse/bin/pt730-plan new --name "Agent LAN" --output agent-lan.json
pt-reverse/bin/pt730-plan add-device agent-lan.json --name R1 --category router --model 2911 --output agent-lan.json
pt-reverse/bin/pt730-plan add-device agent-lan.json --name SW1 --category switch --model 2960-24TT --output agent-lan.json
pt-reverse/bin/pt730-plan add-device agent-lan.json --name SRV1 --category server --model Server-PT --output agent-lan.json
pt-reverse/bin/pt730-plan add-device agent-lan.json --name AP1 --category accesspoint --model AccessPoint-PT --ssid CLASSROOM --output agent-lan.json
pt-reverse/bin/pt730-plan add-module agent-lan.json --device R1 --slot 0/0 --model HWIC-2T --output agent-lan.json
pt-reverse/bin/pt730-plan add-link agent-lan.json --a R1 --pa GigabitEthernet0/0 --b SW1 --pb FastEthernet0/1 --output agent-lan.json
pt-reverse/bin/pt730-plan add-ap-config agent-lan.json --name AP1 --ssid CLASSROOM --channel 6 --auth wpa2-psk --output agent-lan.json
pt-reverse/bin/pt730-plan add-vlan-config agent-lan.json --id 10 --name USERS --network 192.168.10.0/24 --gateway 192.168.10.1 --output agent-lan.json
pt-reverse/bin/pt730-plan add-ios-config agent-lan.json --device R1 --command "enable" --command "configure terminal" --command "end" --output agent-lan.json
pt-reverse/bin/pt730-plan add-server-config agent-lan.json --name SRV1 --http --dns-json '{"enabled":true,"records":[{"name":"www.lab.local","ip":"192.168.10.10"}]}' --output agent-lan.json
pt-reverse/bin/pt730-layout agent-lan.json --style lan --output agent-lan-layout.json
```

生成 SVG 拓扑图：

```bash
pt-reverse/bin/pt730-render svg \
  pt-reverse/examples/simple-lan.json \
  --output simple-lan.svg
pt-reverse/bin/pt730-render svg \
  pt-reverse/examples/simple-lan.json \
  --title "Simple LAN" --legend \
  --theme dark --no-link-labels --no-model-labels --group-by network \
  --output simple-lan.clean.svg
```

生成可导入 diagrams.net/draw.io 的拓扑文件：

```bash
pt-reverse/bin/pt730-render drawio \
  pt-reverse/examples/simple-lan.json \
  --theme paper --group-by network \
  --output simple-lan.drawio
```

生成浏览器可打开的 HTML 预览页：

```bash
pt-reverse/bin/pt730-render html \
  pt-reverse/examples/simple-lan.json \
  --theme dark --no-link-labels --group-by network \
  --output simple-lan.html
```

一次性生成一组审阅附件：

```bash
pt-reverse/bin/pt730-render bundle \
  pt-reverse/examples/simple-lan.json \
  --output-dir simple-lan-render \
  --basename simple-lan \
  --formats svg,drawio,html,markdown,summary \
  --theme paper --title "Simple LAN" --legend --group-by network
```

如果只是要适合报告截图和 agent 审阅的默认效果，可以直接使用报告预设：

```bash
pt-reverse/bin/pt730-render bundle \
  pt-reverse/examples/simple-lan.json \
  --output-dir simple-lan-report \
  --basename simple-lan \
  --preset report
```

默认 bundle 格式为 `svg,drawio,html,markdown,summary`，输出目录内会有：

- `simple-lan.svg`
- `simple-lan.drawio`
- `simple-lan.html`
- `simple-lan.md`
- `simple-lan.summary.json`
- `simple-lan.manifest.json`

如果需要把课程审计或拓扑图质量审计也放进同一个 bundle，在 `--formats` 里追加
`course-audit`、`diagram-audit`、`verification-json` 或 `verification-md`。注意：课程审计不通过时仍会写出审计 JSON 和
manifest，但命令退出码会反映审计失败，方便 CI 或 agent 判断；拓扑图质量审计
只有发现空图或链路端点缺失这类错误时才让命令失败。

可视化渲染选项：

- `--theme light|dark|paper`: 控制 SVG、draw.io、HTML 图的配色。
- `--preset manual|report`: `report` 会使用 paper 主题、自动分组、图例、隐藏链路标签；在 bundle 和 lab plan 中还会默认生成 `diagram-audit`、`verification-json`、`verification-md`。
- `--title <title>`: 给 SVG、draw.io、HTML 图添加可见标题，适合报告截图和视频讲解。
- `--legend`: 给 SVG、draw.io、HTML 图添加设备/链路图例，复杂拓扑或给老师审阅时建议开启。
- `--no-link-labels`: 隐藏 Mermaid/SVG/draw.io/HTML 图中的链路标签，适合复杂拓扑。
- `--no-model-labels`: 隐藏 SVG/draw.io/HTML 图中的设备型号，仅保留设备名。
- `--group-by none|auto|network|vlan|site|category`: 给 SVG、draw.io、HTML 图添加视觉分组框；复杂校园网建议用 `auto` 或 `vlan`，多站点 WAN 建议用 `site`。

拓扑 JSON 还可以加入顶层 `annotations` 数组，为报告图添加说明框：

```json
{
  "annotations": [
    {
      "id": "core-note",
      "kind": "info",
      "target": "R1",
      "title": "Core Gateway",
      "text": "Default gateway and routing validation point."
    },
    {
      "kind": "warning",
      "x": 24,
      "y": 260,
      "text": "Manual IPv6 host configuration remains report metadata."
    }
  ]
}
```

`target` 指向设备名时，Mermaid/SVG/draw.io 会画出连接到该设备的说明框；显式
`x`/`y` 则固定说明框位置。Markdown 会生成 `Diagram Annotations` 表，
summary JSON 会输出 `annotations` 数组和 `counts.annotations`。

如果只想在本次渲染临时加说明框，不改拓扑 JSON，可使用：

```bash
pt-reverse/bin/pt730-render summary plan.json \
  --annotation '{"id":"core-note","target":"R1","title":"Core","text":"Gateway and routing check"}'
```

也可以用 `--annotations annotations.json` 读取 JSON 对象或数组。MCP
`pt730_render` / `pt730_render_bundle` 对应提供 `annotations` 参数。
若需要让 agent 先查询字段规范，可运行 `pt730-render schema`，或通过 MCP
调用 `pt730_schema` 并设置 `target=render`。

输出到文件：

```bash
pt-reverse/bin/pt730-render markdown \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.generated.md
```

生成机器可读摘要：

```bash
pt-reverse/bin/pt730-render summary \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.summary.json
```

生成拓扑图质量审计：

```bash
pt-reverse/bin/pt730-render diagram-audit \
  pt-reverse/examples/simple-lan.json \
  --output simple-lan.diagram-audit.json
```

`diagram-audit` 也支持 `--preset report`、`--group-by`、`--no-link-labels`
等可视化选项，用来审计最终报告预设下的画布密度和分组效果。

拓扑图质量审计会检查空拓扑、缺少 `x/y` 坐标、设备距离过近、断开的组件、
画布过大，以及复杂图是否建议使用 `--group-by` 或 `--no-link-labels`。它只做
离线 JSON 检查，不启动 Packet Tracer；warning 不会让命令失败，真正空图或链路
端点缺失才会返回非零退出码。

生成验证清单：

```bash
pt-reverse/bin/pt730-render verification-plan \
  pt-reverse/examples/server-dhcp-lan.json \
  --format markdown \
  --output server-dhcp.verification.md
```

`verification-plan` 会从 `pc_configs`、`ios_configs` 和 `server_configs`
里提取代表性验证步骤：网关/DNS/服务器 ping、DHCP 客户端租约、IOS
`show` 命令、Server-PT 服务检查、DNS 记录 ping、FTP 登录和简单 PDU
路径检查。JSON 输出适合 agent/MCP 继续执行；Markdown 输出适合课程报告和本人出镜讲解的视频脚本。命令本身只离线生成清单，不会接触 live Packet Tracer。

课程设计审计：

```bash
pt-reverse/bin/pt730-render course-audit \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.audit.json
```

课程审计会检查：

- 服务器网段是否符合 `172.16.1.0/26`
- PC 地址空间是否覆盖 `192.168.0.0/21`
- 必要 VLAN 是否出现
- 代表性主机是否配置
- 链路、网关、地址组是否能汇总到报告

## 离线拓扑模板

`pt730-template` 用内置模板直接生成拓扑 JSON。它不会启动 Packet Tracer，
适合 agent 在不手写 JSON 的情况下快速绘制常见实验拓扑。

查看 schema：

```bash
pt-reverse/bin/pt730-template schema
```

生成星型 LAN，包含 1 台路由器、1 台二层交换机、静态 PC、可选 HTTP
服务器和路由器网关配置：

```bash
pt-reverse/bin/pt730-template lan-star \
  --name DEMO \
  --pcs 4 \
  --servers 1 \
  --network 192.168.10.0/24 \
  --gateway 192.168.10.1 \
  --dns 192.168.10.254 \
  --layout-style lan \
  --output lan-star.json
```

生成双栈 IPv4/IPv6 LAN，包含 1 台 2911 路由器、1 台 2960 交换机、静态 IPv4
主机配置、IPv6 主机元数据、路由器 `ipv6 unicast-routing` 和可渲染 IPv6
地址汇总：

```bash
pt-reverse/bin/pt730-template dual-stack-lan \
  --name DUAL \
  --pcs 2 \
  --servers 1 \
  --ipv4-network 192.168.60.0/24 \
  --ipv4-gateway 192.168.60.1 \
  --ipv6-prefix 2001:db8:60::/64 \
  --ipv6-gateway 2001:db8:60::1 \
  --layout-style lan \
  --output dual-stack-lan.json
```

该模板生成 `pc_configs`、`ipv6_configs`、`server_configs` 和 `ios_configs`。
IPv4 主机配置可继续走现有 live apply；IPv6 PC/Server GUI 写入在 PT 7.3.0
JavaScript API 未验证前保留为手工配置元数据和验证清单，不会在无人值守 live
apply 中强行执行。

生成无线 LAN，包含 1 台路由器、1 台二层交换机、已本地验证的
`AccessPoint-PT`、`Laptop-PT`、可选服务器、静态主机 IP 和 AP/SSID 元数据：

```bash
pt-reverse/bin/pt730-template wireless-lan \
  --name WIFI \
  --aps 2 \
  --laptops 4 \
  --servers 1 \
  --network 192.168.80.0/24 \
  --gateway 192.168.80.1 \
  --ssid CLASSROOM \
  --layout-style lan \
  --output wireless-lan.json
```

无线链路使用 Packet Tracer cable code `8109`。离线 `pt730-safety plan`
在非 strict 模式下会通过并提示 “not live-verified locally”；真正写入 live
Packet Tracer 前仍建议先 `pt730-topo apply --dry-run`，再小批量应用。

生成 router-on-a-stick VLAN 实验，包含 1 台 2911 路由器、1 台 2960 接入交换机、
路由器 802.1Q 子接口、交换机 trunk/access 端口、静态或 DHCP PC、可选每 VLAN
HTTP/DNS 服务器、可选 router DHCP pools 和 VLAN 元数据：

```bash
pt-reverse/bin/pt730-template vlan-router-on-stick \
  --name ROAS \
  --vlans 3 \
  --hosts-per-vlan 2 \
  --servers-per-vlan 1 \
  --address-pool 192.168.20.0/22 \
  --vlan-prefix 24 \
  --vlan-base 10 \
  --native-vlan 10 \
  --domain roas.local \
  --layout-style hierarchical \
  --output vlan-router-on-stick.json
```

如果要让 PC 作为 DHCP client，并在路由器上生成每个 VLAN 的 DHCP pool：

```bash
pt-reverse/bin/pt730-template vlan-router-on-stick \
  --name DHCP \
  --vlans 3 \
  --hosts-per-vlan 2 \
  --servers-per-vlan 1 \
  --client-addressing dhcp \
  --output vlan-router-on-stick-dhcp.json
```

该模板只使用已验证的 `2911`、`2960-24TT`、`PC-PT`、`Server-PT`。生成结果包含
`vlan_configs`、`pc_configs`、`server_configs`、`dhcp_pools` 和 `ios_configs`；
Markdown/summary 渲染会列出 VLAN、网段、网关、802.1Q 子接口、trunk allowed
VLAN、access 端口和 Router DHCP Pools。适合 VLAN、单臂路由、跨 VLAN 通信、
基础 DNS/HTTP 服务和 DHCP 地址分配实验。DHCP client 的 live 租约验证仍属于
guarded 路径；离线生成和报告渲染可以直接使用，真正 live 校验前先 dry-run。

生成二层交换实验，包含双分布交换机、多个接入交换机、VLAN trunk、接入口、
STP root primary/secondary、双链路 EtherChannel Port-channel1、PortFast 和
BPDU Guard，以及每个 VLAN 的代表性静态 PC：

```bash
pt-reverse/bin/pt730-template switching-lab \
  --name L2 \
  --vlans 3 \
  --hosts-per-vlan 2 \
  --access-switches 2 \
  --address-pool 192.168.48.0/22 \
  --vlan-prefix 24 \
  --vlan-base 10 \
  --layout-style campus \
  --output switching-lab.json
```

该模板只使用已验证的 `2960-24TT` 和 `PC-PT`，生成 `vlan_configs`、
`pc_configs` 和多台交换机的 `ios_configs`。它是纯二层实验，PC 默认没有
三层网关，适合验证 VLAN 隔离、同 VLAN 二层连通、STP 阻塞/根桥角色和
EtherChannel 聚合；如果需要跨 VLAN 通信，请使用 `vlan-router-on-stick`、
`campus --l3` 或 `redundant-campus`。

生成 Server-PT 服务实验，包含 1 台 2911 网关路由器、1 台 2960 接入交换机、
1 台 Server-PT、若干客户端 PC、Server-PT HTTP/DNS/FTP/TFTP/Email/NTP/
Syslog/DHCP 服务元数据，以及客户端 DHCP 或静态 IP 配置：

```bash
pt-reverse/bin/pt730-template server-services \
  --name SVC \
  --clients 3 \
  --network 192.168.200.0/24 \
  --domain services.local \
  --services all \
  --layout-style lan \
  --output server-services.json
```

`--services` 可设为 `all`，也可用逗号选择 `http,dns,ftp,tftp,email,ntp,syslog,dhcp`。
包含 `dhcp` 时客户端会生成 DHCP 配置，并在验证计划中产生 DHCP lease 检查；
不包含 `dhcp` 时客户端使用静态地址。该模板适合课程里演示 Web、DNS 解析、
FTP 登录、邮件账号、时间/日志服务和 DHCP 地址池。真正 live 应用前仍建议先
`pt730-safety plan`、`pt730-render verification-plan` 和 `pt730-topo apply --dry-run`。

生成边界安全/NAT/ACL 实验，包含 ISP 路由器、边界路由器、内网、DMZ、Internet
测试主机、NAT overload、外侧入方向 ACL、静态路由、DMZ Web/DNS 服务：

```bash
pt-reverse/bin/pt730-template edge-security \
  --name SEC \
  --inside-hosts 3 \
  --dmz-servers 2 \
  --internet-hosts 1 \
  --inside-network 192.168.10.0/24 \
  --dmz-network 172.16.10.0/24 \
  --wan-network 203.0.113.0/30 \
  --internet-network 198.51.100.0/24 \
  --domain sec.local \
  --layout-style hierarchical \
  --output edge-security.json
```

该模板只使用已验证的 `2911`、`2960-24TT`、`PC-PT`、`Server-PT`，不使用
ASA 或其他 risky 防火墙型号。生成结果包含 `security_policies`，Markdown
和 summary 渲染会直接列出 NAT/ACL 设计意图。

生成串口路由器环，包含 2911、`HWIC-2T` 模块、serial 链路、接口 IP 和
RIPv2 配置：

```bash
pt-reverse/bin/pt730-template router-ring \
  --name WAN \
  --routers 4 \
  --interconnect-pool 10.20.0.0/28 \
  --layout-style ring \
  --output router-ring.json
```

生成多站点 WAN 环网，包含每个站点的路由器、接入交换机、代表 PC、服务器、
HTTP/DNS 服务、串口互联和 RIP/EIGRP/OSPF/static IOS 配置：

```bash
pt-reverse/bin/pt730-template wan-ring \
  --name BRANCH \
  --sites 3 \
  --hosts-per-site 2 \
  --servers-per-site 1 \
  --routing ospf \
  --output wan-ring.json
```

`--routing ospf` 会生成 `router ospf 1`、router-id、站点 LAN passive-interface
和每条直连 LAN/serial 网络的 `network ... area 0`。如果课程只要求 RIP 或
静态路由，也可以把该参数改成 `rip`、`static` 或 `none`；如果要做 Cisco
动态路由课程实验，也可以使用 `--routing eigrp`，它会生成 `router eigrp 100`、
LAN passive-interface 和 wildcard `network ...`。

生成代表性校园网模板，包含核心交换机、服务器 VLAN、多个接入 VLAN、
代表主机、服务器服务和可选三层 IOS 配置：

```bash
pt-reverse/bin/pt730-template campus \
  --name AGENT \
  --cores 2 \
  --segments 4 \
  --hosts-per-segment 2 \
  --servers 4 \
  --l3 --routing ospf \
  --output campus.json
```

`--routing ospf` 会让校园网三层配置生成 `router ospf 1`、router-id、SVI
passive-interface，以及核心互联和各 VLAN 网段的 `network ... area 0`。
如果课程要求 EIGRP、RIP 或静态路由，可改为 `eigrp`、`rip` 或 `static`。

生成冗余双核心校园网模板，包含双核心交换、双上联接入交换机、HSRP 虚拟网关、
STP root primary/secondary、DHCP relay、IOS DHCP pools、NTP/Syslog/SNMP、
Web/DNS/FTP/NMS 服务器服务和可选 RIP/EIGRP/OSPF 配置：

```bash
pt-reverse/bin/pt730-template redundant-campus \
  --name AGENT \
  --segments 4 \
  --hosts-per-segment 2 \
  --servers 4 \
  --routing ospf \
  --output redundant-campus.json
```

该模板会生成 `vlan_configs`、`dhcp_pools`、`redundancy_groups` 和多设备
`ios_configs`。默认服务器网段为 `172.16.1.0/26`，HSRP 网关为
`172.16.1.62`；个人计算机网段从 `192.168.0.0/21` 中按 VLAN 切分。渲染
SVG/draw.io/HTML 时可配合 `--group-by auto` 或 `--group-by vlan` 得到更清晰
的 VLAN 分组视图。

生成综合企业边界拓扑，包含总部 VLAN、服务器区、DMZ、ISP/Internet 测试网、
分支 WAN 串口路由器、NAT overload、外侧 ACL、HTTP/DNS/FTP/Email 服务和
可选 RIP/EIGRP/OSPF/static/BGP 配置：

```bash
pt-reverse/bin/pt730-template enterprise-edge \
  --name ENT \
  --campus-vlans 3 \
  --hosts-per-vlan 2 \
  --campus-servers 4 \
  --branches 2 \
  --branch-hosts 2 \
  --dmz-servers 2 \
  --routing ospf \
  --output enterprise-edge.json
```

如果需要 ISP 边界路由演示，可改用 BGP：

```bash
pt-reverse/bin/pt730-template enterprise-edge \
  --name ENT \
  --campus-vlans 3 \
  --branches 2 \
  --dmz-servers 2 \
  --routing bgp \
  --output enterprise-edge-bgp.json
```

`--routing bgp` 会保留分支到总部的静态可达性，并在企业边界路由器和 ISP
路由器之间生成 eBGP：企业侧 AS 65001，ISP 侧 AS 65000，同时为总部 VLAN、
服务器区、DMZ 和分支网段生成 BGP `network ... mask ...` 语句。

该模板默认生成约 30 台设备和 30 条链路，适合让 agent 一条命令画出复杂、
层次清晰的企业网拓扑。它只使用已验证的 `2911`、`2960-24TT`、`PC-PT`、
`Server-PT` 和 `HWIC-2T`，不使用 ASA/firewall risky 型号。渲染时建议：

```bash
pt-reverse/bin/pt730-render bundle enterprise-edge.json \
  --output-dir enterprise-edge-render \
  --basename enterprise-edge \
  --group-by auto \
  --theme paper \
  --title "Enterprise Edge" \
  --legend
```

生成后可继续走通用离线链路：

```bash
pt-reverse/bin/pt730-safety plan lan-star.json
pt-reverse/bin/pt730-render markdown lan-star.json --output lan-star.md
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run lan-star.json
```

## 离线 Lab Bundle

`pt730-lab` 面向 agent 的“一个规格文件或一个拓扑 plan 生成一套交付产物”
场景。它不会启动 Packet Tracer，也不会通过 live bridge 操作画布；它只是调用已有的
`pt730-template`、`pt730-safety`、`pt730-render bundle` 和
`pt730-config-plan export-configs`，把结果统一写入一个输出目录。

查看 schema：

```bash
pt-reverse/bin/pt730-lab schema
```

最小规格文件示例：

```json
{
  "name": "enterprise-demo",
  "template": "enterprise-edge",
  "template_options": {
    "name": "ENT",
    "campus_vlans": 3,
    "hosts_per_vlan": 2,
    "campus_servers": 4,
    "branches": 2,
    "branch_hosts": 2,
    "dmz_servers": 2,
    "routing": "ospf",
    "layout_style": "campus"
  },
  "render": {
    "basename": "enterprise-demo",
    "preset": "report"
  },
  "strict_safety": false,
  "export_configs": true
}
```

生成完整离线交付目录：

```bash
pt-reverse/bin/pt730-lab template lab-spec.json --output-dir lab-out
```

如果 agent 已经通过 `pt730-compose`、`pt730-layout` 或手写 JSON 得到了一个
`topology.json`，可以直接从现有 plan 打包：

```bash
pt-reverse/bin/pt730-lab plan topology.json \
  --output-dir topology-lab \
  --basename topology \
  --preset report
```

从 bundle 清单生成课程交付索引：

```bash
pt-reverse/bin/pt730-lab report topology-lab/manifest.json \
  --output topology-lab/deliverable.md \
  --title "Campus Topology Deliverable"
```

输出目录包含：

- `topology.json`: 已按模板生成并布局的拓扑 JSON。
- `safety.json`: 离线安全检查报告。
- `render/<basename>.svg`: 可直接放进报告或截图讲解的拓扑图。
- `render/<basename>.drawio`: 可导入 diagrams.net/draw.io 继续微调。
- `render/<basename>.html`: 浏览器可打开的图 + 表格预览页。
- `render/<basename>.md`: 报告可引用的 Markdown 表格。
- `render/<basename>.summary.json`: agent 友好的机器可读摘要。
- `render/<basename>.diagram-audit.json`: 可选的拓扑图质量审计报告。
- `render/<basename>.verification.json`: 可选的机器可读验证清单。
- `render/<basename>.verification.md`: 可选的报告/录屏用验证清单。
- `render/<basename>.manifest.json`: 渲染产物清单。
- `configs/*.cfg`: 从拓扑里的 `ios_configs` 导出的每台设备配置。
- `manifest.json`: lab bundle 总清单，包含输入、输出、render manifest、
  safety report 和 config export manifest。
- `deliverable.md`: 可选，由 `pt730-lab report` 生成，汇总产物路径、安全状态、
  拓扑统计、配置文件和建议录屏验证点。

`template` 可选值与 `pt730-template schema` 一致：`lan-star`、
`dual-stack-lan`、`wireless-lan`、`vlan-router-on-stick`、`switching-lab`、
`server-services`、`edge-security`、`router-ring`、`wan-ring`、`campus`、
`redundant-campus`、`enterprise-edge`。
`template_options` 使用 snake_case 字段名；CLI 风格的短横线字段也会被规范化，
例如 `campus-vlans` 会按 `campus_vlans` 处理。未知模板或未知字段会直接报错，
避免 agent 默默生成不符合预期的拓扑。

`plan` 子命令不读取模板字段，只读取现有 topology JSON；常用命令行选项包括
`--basename`、`--formats`、`--preset`、`--theme`、`--no-link-labels`、`--no-model-labels`、
`--group-by`、`--title`、`--legend`、`--strict-safety`、`--no-configs` 和
`--config-source`。

`report` 子命令只读取现有 `manifest.json`，不会重新生成拓扑，也不会接触
Packet Tracer。默认把 Markdown 输出到 stdout；加 `--output` 时会写入文件并
返回一个小 JSON，便于 agent/MCP 调用后继续处理。

常用开关：

- `strict_safety`: 规格内设为 `true`，或命令行加 `--strict-safety`，会把
  safety warning 也视作失败。普通模式下 warning 仍会写入 `safety.json`，
  但不阻止产物生成。
- `export_configs`: 设为 `false` 时不创建 `configs/`，只生成拓扑和渲染产物。
- `config_source`: 只导出 `ios_configs` 中匹配某个 `source` 的配置记录。
- `render.formats`: 可限制输出格式，例如只要 `["svg", "summary"]`，或追加
  `"diagram-audit"` 做拓扑图质量检查，追加 `"verification-json"` /
  `"verification-md"` 生成验证清单。
- `render.preset`: 设为 `report` 时默认使用 paper 主题、自动分组、图例、隐藏链路标签，并默认生成 `svg,drawio,html,markdown,summary,diagram-audit,verification-json,verification-md`。
- `render.group_by`: 复杂校园网建议用 `auto` 或 `vlan`；企业/分支场景建议用
  `auto` 或 `site`。
- `render.title`: 给 SVG、draw.io、HTML 图添加可见标题。
- `render.legend`: 设为 `true` 时给 SVG、draw.io、HTML 图添加设备/链路图例。
- `render.annotations`: 给 lab bundle 的 `topology.json` 和所有渲染产物加入说明框；
  `pt730-lab template` / `pt730-lab plan` 也可用 `--annotation` 或
  `--annotations` 临时追加说明框。

MCP 调用示例：

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pt730_lab_template","arguments":{"spec":"lab-spec.json","output_dir":"lab-out","compact":true}}}' \
  | pt-reverse/bin/pt730-mcp
printf '%s\n' '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"pt730_lab_plan","arguments":{"plan":"topology.json","output_dir":"topology-lab","basename":"topology","preset":"report","compact":true}}}' \
  | pt-reverse/bin/pt730-mcp
printf '%s\n' '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"pt730_lab_report","arguments":{"manifest":"topology-lab/manifest.json","output":"topology-lab/deliverable.md","title":"Campus Topology Deliverable","compact":true}}}' \
  | pt-reverse/bin/pt730-mcp
```

适用场景：

- agent 已经知道要用某个内置模板，只需要一次调用产出报告附件、拓扑 JSON 和
  IOS 配置文件。
- agent 已经生成了自定义 topology JSON，需要统一补 safety、render、configs
  和 manifest。
- 课程设计、课堂演示或实验报告需要保留一套可复现产物，而不是只保存 `.pkt`。
- 还没有进入 live Packet Tracer 前，先做安全检查、报告渲染和配置审阅。

## 离线 IP/VLAN 规划

`pt730-ip-plan` 把地址池和部门容量规划成 VLSM 子网，并输出可直接合并到
`pt730-compose` 的 `compose.segments`。它不会启动 Packet Tracer。

查看 schema：

```bash
pt-reverse/bin/pt730-ip-plan schema
```

使用示例规划：

```bash
pt-reverse/bin/pt730-ip-plan campus \
  pt-reverse/examples/ip-plan-campus.json \
  --output ip-plan-campus.json
```

输入示例的核心字段：

- `address_pool`: 总 PC 地址池，例如 `192.168.0.0/21`。
- `dns`: 默认 DNS，例如 `172.16.1.11`。
- `default_representative_hosts`: 每个 VLAN 默认绘制几个代表性 PC。
- `groups[]`: 部门或实验室网段，包含 `name`、`hosts`、`vlan`、可选 `core`。

规划规则：

- 按输入顺序分配子网，便于课程设计报告保持可读顺序。
- 每个分组默认额外预留 1 个网关地址。
- 默认网关是子网最后一个可用地址，例如 `192.168.0.0/26` 的网关是
  `192.168.0.62`。
- 输出中的 `capacity_hosts` 是扣除网关后的可用主机容量。
- 输出中的 `compose.segments` 可复制到 campus compose spec 的 `segments`；
  更推荐在 `pt730-compose campus` 中使用 `--segments-from-ip-plan` 直接读取。

完整离线链路示例：

```bash
pt-reverse/bin/pt730-ip-plan campus ip-plan.json --output planned-ip.json
pt-reverse/bin/pt730-compose campus campus-spec.json \
  --segments-from-ip-plan planned-ip.json \
  --output topology.layout.json
pt-reverse/bin/pt730-safety plan topology.layout.json
```

## 离线一键流水线

`pt730-pipeline` 把 IP 规划、拓扑组合、三层配置规划、自动布局、安全检查、
Markdown/summary/SVG/draw.io/HTML 渲染和 `.cfg` 导出串成一个离线命令。
它不会启动 Packet Tracer，适合让 agent 先生成完整可审计产物，再决定
是否进入 live apply。

查看 schema：

```bash
pt-reverse/bin/pt730-pipeline schema
```

使用仓库示例生成一整套离线产物：

```bash
pt-reverse/bin/pt730-pipeline campus \
  --ip-plan pt-reverse/examples/ip-plan-campus.json \
  --compose-spec pt-reverse/examples/compose-campus.json \
  --output-dir compose-campus-out \
  --routing ospf
```

输出目录包含：

- `ip-plan.json`: VLSM 地址规划结果。
- `topology.composed.json`: 组合后的原始拓扑。
- `topology.configured.json`: 写入 `ios_configs` 的拓扑。
- `topology.layout.json`: 自动布局后的最终拓扑 JSON。
- `safety.json`: 离线安全检查报告。
- `topology.summary.json`: agent 友好的摘要。
- `topology.md`: 报告可引用的 Markdown 表格。
- `topology.svg`: 可直接打开预览的离线拓扑图。
- `topology.drawio`: 可导入 diagrams.net/draw.io 继续编辑的拓扑图。
- `topology.html`: 内嵌 SVG 和 Markdown 报告的浏览器预览页。
- `configs/*.cfg`: 每台设备的 IOS 配置文件。
- `manifest.json`: 本次流水线的总清单。

常用参数：

- `--routing rip`: 生成 RIPv2 配置。
- `--routing eigrp`: 生成 EIGRP AS 100、SVI passive-interface 和各三层网段
  wildcard `network ...`，适合 Cisco 路由协议实验。
- `--routing ospf`: 生成 OSPF process 1、router-id、SVI passive-interface
  和各三层网段 `network ... area 0`，更适合演示复杂校园网动态路由。
- `--routing static`: 生成静态路由配置。
- `--routing none`: 只生成二层 access/trunk/VLAN 配置。
- `--layout-style campus|hierarchical|lan|ring|grid|auto`: 指定布局风格。
- `--course-audit`: 额外输出课程设计审计报告；只有满足课程 VLAN/IP
  要求的拓扑才会返回成功。

## 离线拓扑组合

`pt730-compose` 把高层 JSON 规格展开成完整拓扑 JSON。它不会启动 Packet
Tracer，适合 agent 从“我要一个校园网/学院网”的紧凑描述生成设备、端口、
链路、代表性主机 IP、服务器服务和默认布局坐标。

查看 schema 和示例：

```bash
pt-reverse/bin/pt730-compose schema
```

使用仓库示例生成拓扑：

```bash
pt-reverse/bin/pt730-compose campus \
  pt-reverse/examples/compose-campus.json \
  --output compose-campus.layout.json
```

生成后继续走普通离线链路：

```bash
pt-reverse/bin/pt730-safety plan compose-campus.layout.json
pt-reverse/bin/pt730-render markdown compose-campus.layout.json --output compose-campus.layout.md
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run compose-campus.layout.json
```

campus spec 的核心字段：

- `core.count` / `core.prefix`: 生成 `MLS1`、`MLS2` 等核心设备。
- `core.interconnect_pool`: 可选，用于把核心交换机互联链路自动切成
  `/30` 三层传输网段，例如 `10.10.12.0/30` 或 `10.10.0.0/28`。
- `core.interconnect_prefix`: 可选，默认 `/30`。
- `server_switch`: 服务器接入交换机、VLAN 和上联核心。
- `servers[]`: 服务器名称、IP，以及 `services`，例如 HTTP/DNS/FTP/DHCP。
- `segments[]`: 业务网段名称、VLAN、子网、网关、DNS、代表性主机数量。
- `segments[].representative_hosts`: 实际绘制的代表性 PC 数量；课程报告里的
  总容量仍应在设计文档中说明。

默认会使用本地验证安全的 `2960-24TT`、`PC-PT`、`Server-PT`，并自动分配
不冲突的 `FastEthernet0/x` / `GigabitEthernet0/x` 端口。默认还会调用
campus 布局；如果只想生成无坐标拓扑，可以加：

```bash
pt-reverse/bin/pt730-compose campus spec.json --no-layout --output topology.json
```

## 离线配置规划

`pt730-config-plan` 根据拓扑 JSON 的 `links[].vlan`、`pc_configs` 和核心链路
CIDR 元数据生成交换机 IOS 配置，并写入 `ios_configs`。它不会启动 Packet
Tracer。

规则：

- switch-switch 链路生成 trunk。
- switch-PC/server 链路生成 access 端口。
- `link.vlan` 生成 VLAN 声明、trunk allowed VLAN 或 access VLAN。
- 加 `--l3` 后，从 `pc_configs[].gateway/mask` 推导对应 VLAN 的 SVI 网关。
- 加 `--l3` 后，从无 VLAN 的核心交换机链路 `note/subnet/network` 中的
  `x.x.x.x/30` 推导三层互联口地址，并生成 `no switchport`。
- 加 `--routing rip` 后，为有三层接口的交换机生成 RIPv2 `network` 命令。
- 加 `--routing eigrp` 后，为有三层接口的交换机生成 EIGRP AS 100、
  SVI passive-interface 和各直连三层网段的 wildcard `network ...`。
- 加 `--routing ospf` 后，为有三层接口的交换机生成 OSPF process 1、
  router-id、SVI passive-interface 和各直连三层网段的 `network ... area 0`。
- 加 `--routing static` 后，按三层互联图最短路径，为每台三层交换机生成到
  远端 SVI 网段的 `ip route`。
- 已有 `source` 不是 `pt730-config-plan campus` 的手写 `ios_configs` 会保留。

常用命令：

```bash
pt-reverse/bin/pt730-config-plan schema
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --output topology.configured.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --l3 --routing rip \
  --output topology.l3-configured.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --l3 --routing eigrp \
  --output topology.eigrp-configured.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --l3 --routing ospf \
  --output topology.ospf-configured.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --l3 --routing static \
  --output topology.static-configured.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json --ios-only
pt-reverse/bin/pt730-config-plan --compact campus topology.layout.json --ios-only
pt-reverse/bin/pt730-config-plan export-configs topology.configured.json \
  --output-dir configs
pt-reverse/bin/pt730-config-plan --compact export-configs topology.configured.json \
  --output-dir configs --source "pt730-config-plan campus"
```

推荐链路：

```bash
pt-reverse/bin/pt730-ip-plan campus ip-plan.json --output planned-ip.json
pt-reverse/bin/pt730-compose campus campus-spec.json \
  --segments-from-ip-plan planned-ip.json \
  --output topology.layout.json
pt-reverse/bin/pt730-config-plan campus topology.layout.json \
  --l3 --routing ospf \
  --output topology.configured.json
pt-reverse/bin/pt730-config-plan export-configs topology.configured.json \
  --output-dir configs
pt-reverse/bin/pt730-safety plan topology.configured.json
pt-reverse/bin/pt730-render markdown topology.configured.json --output topology.configured.md
```

## 离线自动布局

`pt730-layout` 给拓扑 JSON 自动分配 `x/y` 坐标。它不会启动 Packet Tracer，
适合让 AI 先生成不带坐标或粗略坐标的拓扑，再由 CLI 排成可读画布。

常用命令：

```bash
# 自动判断布局风格，输出到 stdout
pt-reverse/bin/pt730-layout topology.json

# 校园网/学院网推荐，输出到文件
pt-reverse/bin/pt730-layout topology.json \
  --style campus \
  --output topology.layout.json

# 保留已有人工坐标，只给缺坐标的设备补位置
pt-reverse/bin/pt730-layout topology.json \
  --style campus \
  --preserve-existing \
  --output topology.layout.json

# 环形路由拓扑
pt-reverse/bin/pt730-layout topology.json \
  --style ring \
  --canvas-width 1200 \
  --canvas-height 900 \
  --output topology.layout.json

# 控制画布、间距、边距，并输出 compact JSON
pt-reverse/bin/pt730-layout topology.json \
  --style grid \
  --canvas-width 1600 \
  --canvas-height 1000 \
  --spacing-x 220 \
  --spacing-y 180 \
  --margin 100 \
  --compact \
  --output topology.layout.json
```

支持的风格：

- `auto`: 根据设备数量、MLS/核心交换机、服务器、路由器数量自动选择。
- `campus`: 服务器在上方，核心/MLS 在中间，接入交换机和终端在下方，
  适合学院网、园区网、课程设计。
- `lan`: 路由器/交换机横向排列，PC/服务器按父交换机下挂。
- `ring`: 多路由器或核心设备排成环，分支设备向外展开。
- `hierarchical`: 按核心、接入、终端三层分行。
- `grid`: 单纯按网格排布，适合临时检查。

推荐离线顺序：

```bash
pt-reverse/bin/pt730-ip-plan campus ip-plan.json --output planned-ip.json
pt-reverse/bin/pt730-compose campus campus-spec.json --segments-from-ip-plan planned-ip.json --output topology.json
pt-reverse/bin/pt730-config-plan campus topology.json --l3 --routing ospf --output topology.configured.json
pt-reverse/bin/pt730-layout topology.configured.json --style campus --output topology.layout.json
pt-reverse/bin/pt730-safety plan topology.layout.json
pt-reverse/bin/pt730-render markdown topology.layout.json --output topology.layout.md
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run topology.layout.json
```

确认离线输出没问题后，再把 `topology.layout.json` 交给 live `pt730-topo apply`。
如果 `pt730-compose` 没有加 `--no-layout`，它输出的文件已经带坐标，可以直接
进入 `pt730-safety`。

## 拓扑 JSON 格式

最小拓扑示例：

```json
{
  "devices": [
    {"name": "R1", "category": "router", "model": "2911", "x": 220, "y": 180},
    {"name": "SW1", "category": "switch", "model": "2960-24TT", "x": 440, "y": 180},
    {"name": "PC1", "category": "pc", "model": "PC-PT", "x": 660, "y": 180}
  ],
  "links": [
    {
      "a": "R1",
      "pa": "GigabitEthernet0/0",
      "b": "SW1",
      "pb": "FastEthernet0/1",
      "cable": "straight"
    },
    {
      "a": "SW1",
      "pa": "FastEthernet0/2",
      "b": "PC1",
      "pb": "FastEthernet0",
      "cable": "straight"
    }
  ],
  "pc_configs": [
    {
      "name": "PC1",
      "port": "FastEthernet0",
      "ip": "192.168.1.10",
      "mask": "255.255.255.0",
      "gateway": "192.168.1.1"
    }
  ],
  "ios_configs": [
    {
      "device": "R1",
      "commands": [
        "enable",
        "configure terminal",
        "interface GigabitEthernet0/0",
        "ip address 192.168.1.1 255.255.255.0",
        "no shutdown",
        "end"
      ]
    }
  ]
}
```

常用字段：

- `devices`: 设备清单。`name` 是脚本逻辑名，`model` 必须使用 PT 识别的型号。
  `x/y` 可手写，也可省略后用 `pt730-layout` 自动补齐。
- `modules`: 模块安装，例如给 `2911` 加 `HWIC-2T`。
- `links`: 链路清单。`a/pa` 是 A 端设备和端口，`b/pb` 是 B 端设备和端口。
- `pc_configs`: PC/笔记本静态 IP 或 DHCP 配置。
- `server_configs`: Server-PT 的 IP、HTTP、DNS、FTP、DHCP 等服务配置。
- `ios_configs`: 对路由器或 IOS-like 交换机执行的 CLI 命令。

先做安全检查：

```bash
pt-reverse/bin/pt730-safety plan topology.json
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run topology.json
```

## 模型验证流程

查看待验证队列：

```bash
pt-reverse/bin/pt730-models queue
```

当前常用队列已经验证完，`unverified` 为 0。将来如果新增模型，流程如下。

生成单模型验证计划：

```bash
pt-reverse/bin/pt730-models probe-plan 1841
```

离线预览验证步骤：

```bash
pt-reverse/bin/pt730-models validate 1841 --dry-run
```

live 验证：

```bash
pt-reverse/bin/pt730-app --timeout 20 new
pt-reverse/bin/pt730-models validate 1841 --live --record-failure-status risky
```

如果 create/query 通过，还不能立刻标 safe。必须保存、重开、再 query：

```bash
pt-reverse/bin/pt730-app --timeout 20 save-as pt-reverse/live-exports/model-validation/verify-1841.pkt
pt-reverse/bin/pt730-app --timeout 20 open pt-reverse/live-exports/model-validation/verify-1841.pkt
pt-reverse/bin/pt730-topo query --summary
```

确认保存/重开也通过后，记录为 safe：

```bash
pt-reverse/bin/pt730-models record 1841 \
  --status safe \
  --reason 'PT 7.3.0 live validation passed: create/query/save/reopen/query' \
  --evidence 'pt730-models validate 1841 --live ok' \
  --evidence 'save-as/open verify-1841.pkt ok' \
  --save-reopen
```

如果 PT 拒绝创建或查询失败，记录为 risky：

```bash
pt-reverse/bin/pt730-models record 2950T \
  --status risky \
  --reason 'Packet Tracer refused model during create' \
  --evidence 'pt730-topo: Packet Tracer refused device VERIFY-2950T model=2950T'
```

只有严重不应自动化的对象才记录为 blocked。

## 反向查询和导出

查询当前画布原始 JSON：

```bash
pt-reverse/bin/pt730-topo query
```

```bash

```

摘要包括：

- 设备列表
- 链路列表
- 端口 IP、掩码、网关、DNS
- IOS 设备 prompt
- 终端输出尾部
- Server 服务状态
- 从 IOS 输出中解析出的接口、VLAN、RIP network、OSPF/EIGRP/BGP、
  接口 IPv6 地址、OSPFv3、RIPng、IPv4/IPv6 静态路由、管理访问元数据、
  ACL、NAT
- 不可读 link 的降级记录

导出当前画布：

```bash
pt-reverse/bin/pt730-topo export \
  --raw-out current.raw.json \
  --summary-out current.summary.json \
  --markdown-out current.summary.md
```

```bash

```

```bash
pt-reverse/bin/pt730-topo export \
  --from-query current.raw.json \
  --raw-out current.raw.copy.json \
  --summary-out current.summary.json \
  --markdown-out current.summary.md
```

## 常见故障处理

### bridge 是 connected:false

检查：

```bash
pt-reverse/bin/pt730-bridge status
```

处理：

1. 确认 `pt730-bridge start` 已运行。
2. 在 PT 里打开 `Extensions -> Scripting -> Configure PT Script Modules`。
3. 确认 Builder 模块已经 `Start`。
4. 打开 Builder 编辑器，重新运行 bootstrap。
5. 再查 `pt730-bridge status`。

也可以尝试：

```bash
pt-reverse/bin/pt730-recover --notify
```

### 找不到 Builder Code Editor

PT 7.3.0 不一定有新版菜单。先进入：

```text
Extensions -> Scripting -> Configure PT Script Modules
```

选中 Builder 后点 `Edit`，或启动模块后再看 `Extensions` 菜单是否出现
Builder 编辑器入口。

### PT 无法启动

检查脚本能否找到 `PacketTracer7.exe`：

```bash
pt-reverse/bin/pt730-launch status
```

如果本地目录不同：

```bash
export PT_BIN="/path/to/bin"
pt-reverse/bin/pt730-launch start
```

### save-as 报文件不存在

通常是 Wine 工作目录和仓库布局不一致。当前脚本已经支持 `src/bin`。如果还
失败，确认：

```bash
ls "$PT_BIN/PacketTracer7.exe"
```

或者用直接路径模式：

```bash
pt-reverse/bin/pt730-app --timeout 20 save-as output.pkt --direct
```

### 某个模型被拒绝

如果看到类似：

```text
Packet Tracer refused device VERIFY-2950T model=2950T
```

不要在课程拓扑里使用该模型。记录为 risky：

```bash
pt-reverse/bin/pt730-models record 2950T \
  --status risky \
  --reason 'Packet Tracer refused model during create' \
  --evidence 'Packet Tracer refused device VERIFY-2950T model=2950T'
```

### PT 崩溃并生成 dmp

不要继续批量验证。先记录失败模型：

```bash
pt-reverse/bin/pt730-models record MODEL \
  --status risky \
  --reason 'Packet Tracer crashed during validation' \
  --evidence './bin/1.dmp'
```

然后重启：

```bash
pt-reverse/bin/pt730-recover --notify
```

### query 遇到 unreadable link

这通常来自 AP 等设备的内部链路对象。现在导出会降级记录，不会失败。报告里
可以说明该 link 是 PT 内部对象，不影响普通设备/链路/IP 摘要。
