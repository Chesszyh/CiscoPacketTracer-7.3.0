# Cisco Packet Tracer 7.3.0 自动化工具中文使用手册

本文档面向本仓库的实际使用者，说明如何用 `pt-reverse/bin/pt730-*`
工具对固定版本 Cisco Packet Tracer 7.3.0 做离线拓扑审计、受控 live
自动化、拓扑组合、拓扑自动布局、IOS 配置模板渲染、模型安全验证和当前画布反向导出。

本工具链的定位不是替代 Packet Tracer 全部 GUI 功能，而是在 7.3.0 这个
固定版本上提供一套可复现、可审计、尽量不崩溃的命令行工作流。

## 基本原则

1. 固定使用 Cisco Packet Tracer 7.3.0。不要因为新版文档或新版 MCP 项目
   可用就切换版本。
2. 默认先跑离线命令。`pt730-selftest`、`pt730-compose`、`pt730-layout`、
   `pt730-safety`、`pt730-render` 不接触 live Packet Tracer，适合日常修改后验证。
3. live 操作一次只做小步。尤其是新模型验证，必须单个设备、单次创建、
   单次 query、保存、重开后再记录为 safe。
4. 不自动使用 risky/blocked 模型。它们可能被 PT 拒绝、导致查询不完整，
   或触发 7.3.0 崩溃。
5. 保存 `.pkt`、截图、live query 结果可以作为本地证据，但默认不提交到 Git。

## 模型安全状态

模型状态由内置 registry 和 `pt-reverse/pt730/model_validations.json` overlay
共同决定。

查看当前状态：

```bash
pt-reverse/bin/pt730-models manifest
```

当前已验证汇总：

```text
safe: 2911, 2960-24TT, PC-PT, Server-PT, 1841, 1941, 2901,
      2950-24, Laptop-PT, AccessPoint-PT, Cloud-PT

risky: 4321, 4331, 2950T, 3560-24PS, 3650-24PS, Printer-PT,
       WRT300N, ASA5505, ASA5506, IP Phone

blocked: Power Distribution Device

unverified: 当前常用队列为空
```

含义：

- `safe`: 本地 PT 7.3.0 live 创建、query、保存、重开、再 query 通过。
- `unverified`: catalog 里有，但当前环境尚未验证。
- `risky`: PT 拒绝创建、query 不稳定，或已有崩溃风险证据。
- `blocked`: 不应自动化创建或使用。

安全策略会阻止默认使用 risky/blocked 模型。例如：

```bash
pt-reverse/bin/pt730-safety plan topology.json
pt-reverse/bin/pt730-topo apply --dry-run topology.json
```

如果确实要研究 risky 模型，只能使用显式验证命令，并做好崩溃准备。

## 离线拓扑渲染和课程审计

离线渲染不会启动 Packet Tracer，适合写报告、检查 IP 规划、生成拓扑说明。

生成 Mermaid：

```bash
pt-reverse/bin/pt730-render mermaid pt-reverse/examples/simple-lan.json
```

生成 Markdown：

```bash
pt-reverse/bin/pt730-render markdown pt-reverse/examples/simple-lan.json
```

输出到文件：

```bash
pt-reverse/bin/pt730-render markdown \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.generated.md
```

生成机器可读摘要：

```bash
pt-reverse/bin/pt730-render summary \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.summary.json
```

课程设计审计：

```bash
pt-reverse/bin/pt730-render course-audit \
  pt-reverse/course-design/college-network-topology-pt73-safe.json \
  --output pt-reverse/course-design/college-network-topology-pt73-safe.audit.json
```

课程审计会检查：

- 服务器网段是否符合 `172.16.1.0/26`
- PC 地址空间是否覆盖 `192.168.0.0/21`
- 必要 VLAN 是否出现
- 代表性主机是否配置
- 链路、网关、地址组是否能汇总到报告

## 离线拓扑组合

`pt730-compose` 把高层 JSON 规格展开成完整拓扑 JSON。它不会启动 Packet
Tracer，适合 agent 从“我要一个校园网/学院网”的紧凑描述生成设备、端口、
链路、代表性主机 IP、服务器服务和默认布局坐标。

查看 schema 和示例：

```bash
pt-reverse/bin/pt730-compose schema
```

使用仓库示例生成拓扑：

```bash
pt-reverse/bin/pt730-compose campus \
  pt-reverse/examples/compose-campus.json \
  --output compose-campus.layout.json
```

生成后继续走普通离线链路：

```bash
pt-reverse/bin/pt730-safety plan compose-campus.layout.json
pt-reverse/bin/pt730-render markdown compose-campus.layout.json --output compose-campus.layout.md
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run compose-campus.layout.json
```

campus spec 的核心字段：

- `core.count` / `core.prefix`: 生成 `MLS1`、`MLS2` 等核心设备。
- `server_switch`: 服务器接入交换机、VLAN 和上联核心。
- `servers[]`: 服务器名称、IP，以及 `services`，例如 HTTP/DNS/FTP/DHCP。
- `segments[]`: 业务网段名称、VLAN、子网、网关、DNS、代表性主机数量。
- `segments[].representative_hosts`: 实际绘制的代表性 PC 数量；课程报告里的
  总容量仍应在设计文档中说明。

默认会使用本地验证安全的 `2960-24TT`、`PC-PT`、`Server-PT`，并自动分配
不冲突的 `FastEthernet0/x` / `GigabitEthernet0/x` 端口。默认还会调用
campus 布局；如果只想生成无坐标拓扑，可以加：

```bash
pt-reverse/bin/pt730-compose campus spec.json --no-layout --output topology.json
```

## 离线自动布局

`pt730-layout` 给拓扑 JSON 自动分配 `x/y` 坐标。它不会启动 Packet Tracer，
适合让 AI 先生成不带坐标或粗略坐标的拓扑，再由 CLI 排成可读画布。

常用命令：

```bash
# 自动判断布局风格，输出到 stdout
pt-reverse/bin/pt730-layout topology.json

# 校园网/学院网推荐，输出到文件
pt-reverse/bin/pt730-layout topology.json \
  --style campus \
  --output topology.layout.json

# 保留已有人工坐标，只给缺坐标的设备补位置
pt-reverse/bin/pt730-layout topology.json \
  --style campus \
  --preserve-existing \
  --output topology.layout.json

# 环形路由拓扑
pt-reverse/bin/pt730-layout topology.json \
  --style ring \
  --canvas-width 1200 \
  --canvas-height 900 \
  --output topology.layout.json
```

支持的风格：

- `auto`: 根据设备数量、MLS/核心交换机、服务器、路由器数量自动选择。
- `campus`: 服务器在上方，核心/MLS 在中间，接入交换机和终端在下方，
  适合学院网、园区网、课程设计。
- `lan`: 路由器/交换机横向排列，PC/服务器按父交换机下挂。
- `ring`: 多路由器或核心设备排成环，分支设备向外展开。
- `hierarchical`: 按核心、接入、终端三层分行。
- `grid`: 单纯按网格排布，适合临时检查。

推荐离线顺序：

```bash
pt-reverse/bin/pt730-compose campus campus-spec.json --output topology.json
pt-reverse/bin/pt730-layout topology.json --style campus --output topology.layout.json
pt-reverse/bin/pt730-safety plan topology.layout.json
pt-reverse/bin/pt730-render markdown topology.layout.json --output topology.layout.md
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run topology.layout.json
```

确认离线输出没问题后，再把 `topology.layout.json` 交给 live `pt730-topo apply`。
如果 `pt730-compose` 没有加 `--no-layout`，它输出的文件已经带坐标，可以直接
进入 `pt730-safety`。

## 拓扑 JSON 格式

最小拓扑示例：

```json
{
  "devices": [
    {"name": "R1", "category": "router", "model": "2911", "x": 220, "y": 180},
    {"name": "SW1", "category": "switch", "model": "2960-24TT", "x": 440, "y": 180},
    {"name": "PC1", "category": "pc", "model": "PC-PT", "x": 660, "y": 180}
  ],
  "links": [
    {
      "a": "R1",
      "pa": "GigabitEthernet0/0",
      "b": "SW1",
      "pb": "FastEthernet0/1",
      "cable": "straight"
    },
    {
      "a": "SW1",
      "pa": "FastEthernet0/2",
      "b": "PC1",
      "pb": "FastEthernet0",
      "cable": "straight"
    }
  ],
  "pc_configs": [
    {
      "name": "PC1",
      "port": "FastEthernet0",
      "ip": "192.168.1.10",
      "mask": "255.255.255.0",
      "gateway": "192.168.1.1"
    }
  ],
  "ios_configs": [
    {
      "device": "R1",
      "commands": [
        "enable",
        "configure terminal",
        "interface GigabitEthernet0/0",
        "ip address 192.168.1.1 255.255.255.0",
        "no shutdown",
        "end"
      ]
    }
  ]
}
```

常用字段：

- `devices`: 设备清单。`name` 是脚本逻辑名，`model` 必须使用 PT 识别的型号。
  `x/y` 可手写，也可省略后用 `pt730-layout` 自动补齐。
- `modules`: 模块安装，例如给 `2911` 加 `HWIC-2T`。
- `links`: 链路清单。`a/pa` 是 A 端设备和端口，`b/pb` 是 B 端设备和端口。
- `pc_configs`: PC/笔记本静态 IP 或 DHCP 配置。
- `server_configs`: Server-PT 的 IP、HTTP、DNS、FTP、DHCP 等服务配置。
- `ios_configs`: 对路由器或 IOS-like 交换机执行的 CLI 命令。

先做安全检查：

```bash
pt-reverse/bin/pt730-safety plan topology.json
pt-reverse/bin/pt730-topo --timeout 1 apply --dry-run topology.json
```

## live 拓扑创建

先 dry-run：

```bash
pt-reverse/bin/pt730-topo apply --dry-run pt-reverse/examples/simple-lan.json
```

真正创建：

```bash
pt-reverse/bin/pt730-topo apply pt-reverse/examples/simple-lan.json
```

清空当前画布后创建：

```bash
pt-reverse/bin/pt730-topo apply --replace pt-reverse/examples/simple-lan.json
```

大拓扑建议分批：

```bash
pt-reverse/bin/pt730-topo apply --replace --batch-size 2 pt-reverse/examples/two-router-serial-configured.json
```

严格模式下 warning 也会失败：

```bash
pt-reverse/bin/pt730-topo apply --strict-safety pt-reverse/examples/simple-lan.json
```

保存当前 PT 文件：

```bash
pt-reverse/bin/pt730-app --timeout 20 save-as output.pkt
```

打开已有 PT 文件：

```bash
pt-reverse/bin/pt730-app --timeout 20 open output.pkt
```

新建空白文件：

```bash
pt-reverse/bin/pt730-app --timeout 20 new
```

注意：`new` 会清空当前工作区。使用前应确认不需要保留当前画布。

## 模型验证流程

查看待验证队列：

```bash
pt-reverse/bin/pt730-models queue
```

当前常用队列已经验证完，`unverified` 为 0。将来如果新增模型，流程如下。

生成单模型验证计划：

```bash
pt-reverse/bin/pt730-models probe-plan 1841
```

离线预览验证步骤：

```bash
pt-reverse/bin/pt730-models validate 1841 --dry-run
```

live 验证：

```bash
pt-reverse/bin/pt730-app --timeout 20 new
pt-reverse/bin/pt730-models validate 1841 --live --record-failure-status risky
```

如果 create/query 通过，还不能立刻标 safe。必须保存、重开、再 query：

```bash
pt-reverse/bin/pt730-app --timeout 20 save-as pt-reverse/live-exports/model-validation/verify-1841.pkt
pt-reverse/bin/pt730-app --timeout 20 open pt-reverse/live-exports/model-validation/verify-1841.pkt
pt-reverse/bin/pt730-topo query --summary
```

确认保存/重开也通过后，记录为 safe：

```bash
pt-reverse/bin/pt730-models record 1841 \
  --status safe \
  --reason 'PT 7.3.0 live validation passed: create/query/save/reopen/query' \
  --evidence 'pt730-models validate 1841 --live ok' \
  --evidence 'save-as/open verify-1841.pkt ok' \
  --save-reopen
```

如果 PT 拒绝创建或查询失败，记录为 risky：

```bash
pt-reverse/bin/pt730-models record 2950T \
  --status risky \
  --reason 'Packet Tracer refused model during create' \
  --evidence 'pt730-topo: Packet Tracer refused device VERIFY-2950T model=2950T'
```

只有严重不应自动化的对象才记录为 blocked。

## IOS 高层配置模板

`pt730-ios-template` 把高层 JSON 渲染为 IOS 命令，避免手写大段 CLI。

查看 schema：

```bash
pt-reverse/bin/pt730-ios-template schema
```

支持能力：

- VLAN
- access 端口
- trunk 端口和 allowed VLAN
- 三层接口 IP
- interface ACL 绑定：`acl_in`、`acl_out`
- RIP v2
- 静态路由
- standard ACL
- extended ACL
- NAT inside/outside
- NAT overload
- 多设备 `devices` 数组

单设备模板示例：

## 反向查询和导出

查询当前画布原始 JSON：

```bash
pt-reverse/bin/pt730-topo query
```

查询摘要：

```bash
pt-reverse/bin/pt730-topo query --summary
```

摘要包括：

- 设备列表
- 链路列表
- 端口 IP、掩码、网关、DNS
- IOS 设备 prompt
- 终端输出尾部
- Server 服务状态
- 从 IOS 输出中解析出的接口、VLAN、RIP network、静态路由、ACL、NAT
- 不可读 link 的降级记录

导出当前画布：

```bash
pt-reverse/bin/pt730-topo export \
  --raw-out current.raw.json \
  --summary-out current.summary.json \
  --markdown-out current.summary.md
```

对保存过的 query 离线生成摘要：

```bash
pt-reverse/bin/pt730-topo summarize-query current.raw.json
```

对保存过的 query 离线导出：

```bash
pt-reverse/bin/pt730-topo export \
  --from-query current.raw.json \
  --raw-out current.raw.copy.json \
  --summary-out current.summary.json \
  --markdown-out current.summary.md
```

如果遇到 AP 等设备产生没有 `getPort1/getPort2` 的内部 link，导出不会失败，
会在 links 中写入：

```json
{
  "index": 0,
  "status": "unreadable",
  "error": "link object does not expose getPort1/getPort2"
}
```

## 常见故障处理

### bridge 是 connected:false

检查：

```bash
pt-reverse/bin/pt730-bridge status
```

处理：

1. 确认 `pt730-bridge start` 已运行。
2. 在 PT 里打开 `Extensions -> Scripting -> Configure PT Script Modules`。
3. 确认 Builder 模块已经 `Start`。
4. 打开 Builder 编辑器，重新运行 bootstrap。
5. 再查 `pt730-bridge status`。

也可以尝试：

```bash
pt-reverse/bin/pt730-recover --notify
```

### 找不到 Builder Code Editor

PT 7.3.0 不一定有新版菜单。先进入：

```text
Extensions -> Scripting -> Configure PT Script Modules
```

选中 Builder 后点 `Edit`，或启动模块后再看 `Extensions` 菜单是否出现
Builder 编辑器入口。

### PT 无法启动

检查脚本能否找到 `PacketTracer7.exe`：

```bash
pt-reverse/bin/pt730-launch status
```

如果本地目录不同：

```bash
export PT_BIN="/path/to/bin"
pt-reverse/bin/pt730-launch start
```

### save-as 报文件不存在

通常是 Wine 工作目录和仓库布局不一致。当前脚本已经支持 `src/bin`。如果还
失败，确认：

```bash
ls "$PT_BIN/PacketTracer7.exe"
```

或者用直接路径模式：

```bash
pt-reverse/bin/pt730-app --timeout 20 save-as output.pkt --direct
```

### 某个模型被拒绝

如果看到类似：

```text
Packet Tracer refused device VERIFY-2950T model=2950T
```

不要在课程拓扑里使用该模型。记录为 risky：

```bash
pt-reverse/bin/pt730-models record 2950T \
  --status risky \
  --reason 'Packet Tracer refused model during create' \
  --evidence 'Packet Tracer refused device VERIFY-2950T model=2950T'
```

### PT 崩溃并生成 dmp

不要继续批量验证。先记录失败模型：

```bash
pt-reverse/bin/pt730-models record MODEL \
  --status risky \
  --reason 'Packet Tracer crashed during validation' \
  --evidence './bin/1.dmp'
```

然后重启：

```bash
pt-reverse/bin/pt730-recover --notify
```

### query 遇到 unreadable link

这通常来自 AP 等设备的内部链路对象。现在导出会降级记录，不会失败。报告里
可以说明该 link 是 PT 内部对象，不影响普通设备/链路/IP 摘要。

## Git 管理约定

不要提交：

- `src/`
- `*.dmp`
- `pt-reverse/live-exports/`
- `pt-reverse/.tmp/`
- `pt-reverse/docs/`
- `pt-reverse/screenshots/`

```bash
git status --short --branch
git diff --check
git diff --name-only | rg '^(src/|pt-reverse/docs/|pt-reverse/screenshots/|pt-reverse/upstream/)' || true
git submodule status
python3 -m unittest discover -s pt-reverse/tests -p 'test_*.py'
pt-reverse/bin/pt730-selftest
```

```text
0dbf437dd3bb913653fdbb23c660105ceaab0d31 pt-reverse/upstream/MCP-Packet-Tracer
```
